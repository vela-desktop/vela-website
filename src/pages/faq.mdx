Short answers to the questions that come up most. Each one links to where the full story lives.

## About Vela

### What is Vela?

A desktop environment for Linux: the taskbar, Start menu, windows, notifications, file manager and settings you see and use every day. Vela has its own Wayland compositor and Vulkan renderer, a Qt Quick shell, and a file manager and settings app built to match, all designed as one desktop.

### Why build a new desktop instead of improving an existing one?

Because much of what makes a desktop feel modern happens underneath the theme: when a frame is drawn, how sharp a window is at 125%, whether an animation keeps up with your monitor. Getting those right meant owning the whole pipeline, from the moment an app sends a frame to the moment it lights up on the screen. [Why Vela?](/blog/why-vela/) and [Why Vela has its own renderer](/blog/own-renderer/) tell the longer story.

### Is it based on KDE Plasma?

No. The compositor, the heart of any desktop, is Vela's own, and so are the renderer, the shell, Files and Settings. Building a whole desktop environment is a huge undertaking, so Vela borrows a few smaller pieces from KDE to lighten the load: the KDE wallet, icon themes and color schemes. That's also why Qt and KDE apps look and behave as they do in Plasma, and why Chrome, Brave and VS Code keep their saved logins.

Vela is moving away from those pieces one at a time. The polkit agent and Bluetooth are already its own, and since 0.1 neither the KDE portal nor Plasma Workspace is required: dialogs go through the GTK portal, screenshots and screen sharing through the wlr one. A portal of Vela's own is on the roadmap for 0.3. The goal is for Vela to be fully independent, but KDE apps will stay its recommended companions for a long time.

### Is it ready for daily use?

I use it every day, and since 0.1 it's in beta: numbered, signed releases that pass the full GPU test suites on AMD and NVIDIA before they're published. It isn't a stable release yet, though, and it hasn't been tested on every GPU and driver. If you try it, keep another desktop or a TTY available. The stable release will be 1.0.

### Is it free?

Yes. Vela is free software under the [GPL‑3.0‑or‑later](https://github.com/vela-desktop/vela/blob/main/LICENSE) license, and developed in the open on [GitHub](https://github.com/vela-desktop/vela).

## Hardware and compatibility

### Which distributions are supported?

Today, {listOf(DISTROS)}, with signed Beta packages and an updater, `vela-update`. Fedora and Ubuntu support are newer and have had less testing on real hardware. Other distributions will be supported in the future. In the meantime, you can build and install Vela on any distribution that ships {SUPPORT.wlroots}, although it isn't officially supported there yet. The [install page](/install/) covers both.

### Which GPUs does it work with?

Any GPU with a {SUPPORT.vulkan} driver: {SUPPORT.drivers}. Vela is developed on an AMD Radeon RX 9070 XT, and that's where it's tested the most; its GPU test suites also run on an NVIDIA GeForce RTX 4070 Laptop GPU. The [hardware coverage]({LINKS.hardware}) page says exactly what has been verified on the others.

### Does it work with NVIDIA?

Yes, with {SUPPORT.nvidiaDriver}. Vela has NVIDIA-specific handling, its GPU tests run on an NVIDIA machine too, and it gets reports from testers. Real sessions on NVIDIA have had less testing than on AMD, though, especially screen sharing and suspend. Reports are very welcome.

### Can I run it in a virtual machine?

With GPU passthrough, yes: to Vela, it's a real GPU. With a virtual GPU, not yet: on virtio-gpu with Venus, Vela starts Vulkan but crashes on its first frame, while sharing a buffer with the host. [#19](https://github.com/vela-desktop/vela/pull/19) has tracing to find out where and why, and a step-by-step diagnostic guide, on a branch kept for this investigation, but the cause is still unknown. If you're looking for a first contribution, this is a great one.

### Does it run on X11?

No. Vela is a Wayland desktop, a choice it shares with every modern desktop and compositor. X11 apps and games still work through Xwayland, which starts on its own when an app needs it.

### Can I game on it?

Yes. Fullscreen games can go straight to the display without passing through the compositor (direct scanout), with variable refresh rate (FreeSync and G‑Sync) and tearing support where the game asks for it. Steam and older games run through Xwayland, at the monitor's native resolution even when the screen is scaled.

### Does it support fractional scaling and multiple monitors?

Yes, and fractional scaling is one of the things Vela was designed around. When an app renders at the screen's scale, its pixels reach the display one to one, even at 125% or 175%, and an automated test checks it bit for bit. Each monitor can have its own scale and refresh rate, and monitors can be plugged in and out while Vela runs.

### Will my apps look right?

Qt and KDE apps follow Vela's light and dark modes and accent colors, and so do GTK apps. Apps that draw their own title bar, like Chromium with tabs on top, keep it; the others get Vela's.

### Which apps go well with Vela?

Vela brings its own file manager and settings, and for the rest I recommend KDE apps: KWallet for saved passwords, Kate, the calculator, and Konsole, Vela's terminal for now (Super+Enter). GTK and other Qt apps work just as well; use whatever you prefer.

## Using Vela

### Can I try it without replacing my desktop?

Yes. Vela can run in a window inside your current Wayland desktop, without installing anything. And installing it doesn't replace anything either: it adds a session to your login screen, next to the ones you already have. See [Install](/install/#try-it-without-logging-out).

### Can I customize it?

Some things already: light and dark modes, wallpaper, accent colors, and the taskbar's alignment. The priority is good defaults first, but customization will be part of Vela, including something like KDE's themes. [On customization](/blog/about-customization/) explains the plan.

### Is there a tiling mode?

Not today. Vela has snap layouts, Snap Assist and virtual desktops, but no tiling window manager. If you'd like to build one, [open an issue](https://github.com/vela-desktop/vela/issues) and let's talk.

### Which languages does it speak?

English and Italian, switched live in *Settings → Time & language*. More languages are on the [roadmap](https://github.com/vela-desktop/vela/blob/main/docs/roadmap.md).

### What happens if it crashes?

The compositor restarts on its own and your Qt and KDE apps reconnect to it. If the screen was locked, Vela comes back locked. If only the shell crashes, your windows stay open while it restarts.

### How do I update it?

From *Settings → System → Updates*: Vela checks once a day, sends a notification when a new version is out, and installs it with **Install now**. In a terminal, it's `vela-update`. On the Beta channel you get each new release, prebuilt and verified; on Experimental, the latest commit on `main`, built on your machine. The last three versions stay cached, so you can go back if an update causes trouble. The [install page](/install/#updating) has the details.

## Getting involved

### I found a bug. What should I do?

Run `vela-report`. It collects the diagnostics you choose, lets you review every file, and uploads nothing. Then [open an issue](https://github.com/vela-desktop/vela/issues) and attach the ZIP it made.

### How can I contribute?

Testing on your hardware and reporting what you find is already a big help. For code, read the [contribution guide](https://github.com/vela-desktop/vela/blob/main/CONTRIBUTING.md), and open an issue before larger changes. Ideas are welcome too.

### What's coming next?

Fixes to the 0.1 beta as 0.1.x releases, then touch, pen, input methods and an on-screen keyboard in 0.2. The [roadmap](https://github.com/vela-desktop/vela/blob/main/docs/roadmap.md) has the rest, and the [journal](/blog/) follows the work as it happens.
