Vela is beta software. You can use it every day, and every release passes the full GPU test suites on AMD and NVIDIA before it's published, but it isn't a stable release yet, and it hasn't been tested on every GPU and driver. Read this page before installing. It takes five minutes, and it can save you an evening.

<Aside title="Before you start" tone="caution">
  Keep a working desktop session, or at least a TTY, that you can fall back to. Installing Vela doesn't replace your current desktop: it adds a new session to the login screen, next to the ones you already have.
</Aside>

## What you need

- **A GPU with {SUPPORT.vulkan}.** {SUPPORT.drivers}.
- **A login screen that lists Wayland sessions**, such as SDDM or Plasma Login.
- **The usual Linux services** for the features that need them: NetworkManager for Wi‑Fi, BlueZ for Bluetooth, PipeWire and WirePlumber for sound, UDisks2 for drives, xdg-desktop-portal for screen sharing, and Xwayland for X11 apps and games.

Vela is developed and tested daily on an AMD Radeon RX 9070 XT with Mesa/RADV. NVIDIA, Intel, NVK, virtual machines and hybrid-GPU laptops are supported paths, but have had less testing. The [hardware coverage]({LINKS.hardware}) page lists exactly what has been verified and where.

## Try it without logging out

The safest first look: build Vela and run it in a window inside your current Wayland desktop, like a virtual monitor. Nothing is installed.

```sh
git clone https://github.com/vela-desktop/vela.git
cd vela
cmake -B build -G Ninja
cmake --build build
sh scripts/run-nested.sh
```

You'll need the build dependencies listed under [Other distributions](#other-distributions) below, or the [lists for every distribution](https://github.com/vela-desktop/vela/blob/main/docs/development.md#distribution-dependencies) in the developer guide. Your host desktop keeps the Super key, so in nested mode many shortcuts also work with Alt; the [shortcut reference](https://github.com/vela-desktop/vela/blob/main/docs/shortcuts.md) lists them.

A nested session is great for exploring, but it can't tell you whether Vela works with your monitor and driver directly. For that, you need a real session.

## Beta or Experimental

`vela-update` installs Vela on Arch, {SUPPORT.fedora} and {SUPPORT.ubuntu} as a native package, and keeps it updated. It offers two channels:

- **Beta**, the `vela` package, is the one to pick. It installs the newest numbered [release](https://github.com/vela-desktop/vela/releases): prebuilt, signed, and verified with Cosign before it's installed. If a package can't be verified, `vela-update` stops without installing anything.
- **Experimental**, the `vela-git` package, follows the latest commit on `main`, and `vela-update` builds it on your machine. It gets every change as soon as it lands, and every regression too.

The commands below install the Beta. They clone Vela at its latest release, so the `vela-update` that checks every signature is the released one too; Git will say the checkout is a "detached HEAD", which is expected. Without `--channel beta`, the first installation is Experimental. After that, the installed package decides the channel, and *Settings → System → Updates* can switch it.

## Arch Linux, CachyOS, EndeavourOS

Run:

<BetaCommands before={['sudo pacman -S --needed git curl base-devel cosign']} />

`vela-update` handles the first installation too. It downloads the release's `vela` package, checks its SHA-256 checksum and its signed build provenance with Cosign, and installs it with pacman. You don't need a GitHub account or the GitHub CLI.

For Experimental, run `sh vela/packaging/vela-update` instead: it builds `vela-git` from the latest commit on `main`.

## Fedora 44

On {SUPPORT.fedora} (x86_64), Vela installs as a native `vela` RPM, with the same updater. {SUPPORT.fedora} doesn't ship Cosign in its repositories, and the Beta can't be installed without it, so install the official Cosign {COSIGN.version} RPM from Sigstore first. The second line checks the download against the checksum Sigstore published, and stops if it doesn't match:

<CosignCommands format="rpm" />

Only get Cosign from the official Sigstore releases: Vela trusts it to check everything else. Then install Vela:

<BetaCommands before={['sudo dnf install git curl rpm-build dnf5-plugins']} />

<Aside title="Fedora support is new">
  The RPMs are built and test-installed in a fresh {SUPPORT.fedora} container before every release, but they've had little testing on real hardware so far. Other Fedora releases, other DNF-based distributions and the immutable variants, such as Silverblue and Kinoite, aren't supported by the installer. There you can [build from source](#other-distributions).
</Aside>

On {SUPPORT.ubuntu}, Vela installs as a native `vela` DEB, again with `vela-update`. Enable the *universe* repository first. The Beta needs Cosign here too; install the official Cosign {COSIGN.version} DEB from Sigstore, checked against its published checksum:

Then install Vela:

On Ubuntu, Experimental always builds Vela on your machine: `vela-update` installs the build dependencies with APT, compiles the selected commit, and installs the result as a DEB. It takes a while; `--jobs` sets how many parallel jobs the build uses.

<Aside title="Ubuntu support is the newest">
  CI builds the DEB and test-installs it in a fresh {SUPPORT.ubuntu} container, and it has been tried in a virtual machine with GPU passthrough, but real hardware hasn't been tested much yet. Other Ubuntu releases aren't supported.
</Aside>

## Updating

*Settings → System → Updates* shows whether an update is available and what's new: a Beta release's notes, or Experimental's commits. Vela checks by itself once a day, never on a metered connection, and sends a notification when there's something new. **Install now** runs `vela-update` in a terminal, where the package manager asks for your password. When it's done, sign out and back in to use the new version.

From a terminal, it's the same command:

```sh
vela-update            # update if something new is available
vela-update --check    # only check, and list the changes
```

On the Beta, `--force` reinstalls the current release, and `--tag=v0.x.y` goes back to an earlier one: a newer Beta is never replaced by an older one without it. On Experimental, `--build` always builds locally, `--jobs 2` builds with fewer parallel jobs, and `--branch` or `--commit` install a branch or an exact commit, for that run only. The [installation guide](https://github.com/vela-desktop/vela/blob/main/docs/installation.md#updating-selecting-revisions-and-rollback) explains every option, along with test builds and troubleshooting.

The last three packages of each channel stay in `~/.cache/vela-update/packages/`. If an update goes wrong, reinstall the previous one. Pick one exact file, never all of them at once:

```sh
# Arch
sudo pacman -U ~/.cache/vela-update/packages/<package>.pkg.tar.zst
# Fedora
sudo dnf install ~/.cache/vela-update/packages/<package>.x86_64.rpm
# Ubuntu
sudo apt-get install --allow-downgrades --reinstall ~/.cache/vela-update/packages/<package>_amd64.deb
```

## Other distributions

Other distributions will be supported in the future. Until then, you can build Vela from source on any distribution that ships {SUPPORT.wlroots}, although it isn't officially supported there yet, and there's no updater: you rebuild by hand. You need CMake 3.22 or newer, Ninja, a C17 and C++20 compiler, {SUPPORT.wlroots}, Qt 6.7 or newer with its Linguist tools, LayerShellQt, Vulkan headers and loader, `glslc`, GBM, libdrm, FreeType, HarfBuzz, Fontconfig and PAM. librsvg is optional: it draws app icons in the title bar.

On other **Fedora** releases, for example:

```sh
sudo dnf install git cmake ninja-build gcc gcc-c++ pkgconf-pkg-config \
    wlroots-devel wayland-devel wayland-protocols-devel libxkbcommon-devel \
    pixman-devel libinput-devel libdrm-devel mesa-libgbm-devel \
    qt6-qtbase-devel qt6-qtbase-private-devel qt6-qtdeclarative-devel \
    qt6-qttools-devel qt6-qtsvg-devel qt6-qtwayland-devel layer-shell-qt-devel \
    vulkan-headers vulkan-loader-devel glslc freetype-devel harfbuzz-devel \
    fontconfig-devel pam-devel polkit-devel librsvg2-devel cairo-devel \
    zlib-devel gtest-devel python3 python3-numpy python3-pillow shared-mime-info \
    pipewire-devel wireplumber-devel pipewire pipewire-utils wireplumber
```

The developer guide also has the package list for [openSUSE Tumbleweed](https://github.com/vela-desktop/vela/blob/main/docs/development.md#distribution-dependencies). That one is experimental: it isn't checked by CI yet.

Then build and install:

```sh
git clone https://github.com/vela-desktop/vela.git
cd vela
cmake -B build -G Ninja
cmake --build build
sudo cmake --install build
```

This installs into `/usr/local`, plus `/etc/pam.d` and `/etc/xdg`. If Vela doesn't appear on the login screen, your display manager may not look there:

```sh
sudo ln -s /usr/local/share/wayland-sessions/vela.desktop /usr/share/wayland-sessions/
```

## First login

Log out, pick **Vela** on the login screen, and log in. A few things to know:

- **Super** opens Start, **Super+Tab** opens Task View, **Super+arrows** snap windows, and **Super+A**, **Super+N** and **Super+V** open quick settings, notifications and clipboard history.
- The interface speaks **English and Italian**. Switch it in *Settings → Time & language*. It changes right away.
- If the compositor crashes, it restarts on its own and your apps reconnect. If the screen was locked, it comes back locked.

## If something goes wrong

Run `vela-report`. It builds a ZIP with your description and the diagnostics you choose to include, shows you every file before exporting, and uploads nothing. Then [open an issue](https://github.com/vela-desktop/vela/issues) and attach it. From a TTY or over SSH, use `vela-report --cli`.

Every report helps, especially from hardware other than the development machine.
